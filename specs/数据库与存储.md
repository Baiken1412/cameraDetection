# 数据库与存储

## 关注主题（Topic of Concern）

MySQL 数据库管理、检测记录持久化、图像存储、轨迹管理。

---

## 需求描述

### 1. 数据库连接池

- 使用 PyMySQL + DBUtils 连接池
- 线程安全的并发访问
- 连接池大小可配置（默认 5-20 连接）
- 空闲连接自动回收

### 2. 数据表

| 表名 | 用途 |
|---|---|
| 摄像头配置表 | 存储 RTSP 地址、名称、区域、yolo_pool_id 等 |
| 检测记录表 | 存储检测时间、人数、图片路径、置信度等 |
| 轨迹表 | 存储人员移动轨迹 |
| app_person | 人员信息目录（用于 ReID 命名） |

### 3. 核心操作

- `get_all_cameras()` — 获取所有摄像头配置
- `save_detection_record()` — 保存检测记录
- `merge_trajectory()` — 合并轨迹（60 秒窗口内）
- `update_record_status()` — 更新记录状态

### 4. 图像存储

- 文件系统模式：保存到指定目录，命名规则 `{camera_id}_{timestamp}.jpg`
- Base64 模式：编码后存入数据库
- JPEG 质量可配置（默认 95）
- 最大宽度限制（默认 1920）
- 保存路径可配置

### 5. 记录去重规则

| 规则 | 参数 | 默认值 | 说明 |
|---|---|---|---|
| 最小记录间隔 | min_record_interval | 10 秒 | 同一摄像头 10 秒内不重复记录 |
| 保存后等待 | detection_wait_after_save | 120 秒 | 保存记录后 2 分钟内降低检测频率 |
| 轨迹合并窗口 | trajectory_merge_interval | 60 秒 | 60 秒内的检测合并为同一轨迹 |
| 长时间滞留 | long_track_threshold | 60 秒 | 超过 60 秒判定为长时间滞留 |

```json
{
  "DATABASE_CONFIG": {
    "host": "localhost",
    "port": 3306,
    "user": "root",
    "password": "******",
    "database": "caseappdb",
    "charset": "utf8mb4"
  },
  "RTSP_MONITOR_CONFIG": {
    "image_save_path": "D:/appdata/uploadPath/caseapp",
    "save_image_to_file": true,
    "min_record_interval": 10,
    "detection_wait_after_save": 120,
    "trajectory_merge_interval": 60,
    "long_track_threshold": 60
  }
}
```
